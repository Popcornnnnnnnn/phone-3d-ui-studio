# 连接、开局与恢复体验优化

日期：2026-09-28。实现交给 GPT-6 Sol；主代理负责工程验收，用户负责视觉与真机体验验收。

## 本轮目标

让用户明确知道现在处于哪一步、接下来在哪台设备操作，并减少重复配对。保留已经调整好的精细模型、屏幕和材质，以及现有真实运动驱动物理的行为。

## 实施范围与验收标准

1. **连接连续性**：Mac 重开本地会话时优先尝试复用上一次成功的桥接地址端口。端口被占用时使用独立新会话并明确提示重新扫码，绝不接管已有服务。复用端口不能保证网络地址不变；网络变化仍须明确提示。关闭应用仍须释放本实例的服务。
2. **分步引导**：Mac 与 iPhone 区分未连接、连接中、已连接但追踪未就绪、就绪、游戏中、暂停。基于实际状态显示，不把保存地址或相机正常等同于连接完成。默认主体验为 Marble；清楚解释 iPhone 的 Tracking 同时服务于 Mac 的 Marble 和 Tracking。
3. **暂停与恢复**：给出可操作的暂停原因；明确恢复追踪后需要重新校准并开始新回合，重开清空旧球。保留追踪丢失时冻结、显式开局、观察者权限和后台暂停行为，不自动开始摄像头或恢复物理。
4. **已知交互缺陷**：修复 Mac 内嵌页面的本地视频选择器，验证选择和取消。统一关键按钮用语和相关使用文档，不重做整个界面。
5. **视觉与打包一致性**：保留原 GLB 和当前材质、非绿色屏幕。个人构建必须使用 `npm run app:build:local`，并通过 `npm run app:smoke -- --with-local-model`。精细模型缺失时应有可见说明，普通公开构建继续允许使用简化模型。

### 主代理独立验收

按用户最新要求，今后视觉检查均交给用户；主代理完成代码、构建与功能验证后提供具体检查清单，不再以等待自己的视觉检查阻塞交付。本轮检查三个工作区的模型与默认屏幕、旋转缩放、深浅外观、切回前台后的画面恢复。

真实 iPhone 与 Mac 同一 Wi-Fi，连续玩五分钟，完成十次接球、三次补球，以及一次中断后重新校准开局。确认连接提示、跟手程度、跨屏画面与震动反馈。自动测试与模拟器结果不代替这一项。
