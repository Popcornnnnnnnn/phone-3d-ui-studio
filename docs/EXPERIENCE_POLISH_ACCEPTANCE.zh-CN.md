### 后续发现：原生实时投屏无画面（2026-09-28）

此前通过了本地视频交互，但未覆盖原生 WKWebView 的实际 H.264 投屏链路。这是本轮工程验收的遗漏。

- 用户反馈后读取当前桥接诊断：iPhone 已采集、编码并发送画面，Mac 已收到数据；145 条接收记录均没有成功渲染帧，其中包含 58 条窗口可见且有焦点的记录。该故障不能归因于窗口被遮挡。
- 无窗口、禁止激活的 WKWebView 纯解码测试，用本项目编码器生成与现场一致的 960 × 2088、60 fps 编码配置、`avc1.42002a` 合成样本。旧配置在收到第 3 帧前因未输出帧达到 2 个而重置；36 次输入产生 17 次重置，实时输出为零。
- 使用项目已有的硬件解码 / AVCC / 8 帧与 250 ms 缓冲限制后，第 5 次输入开始输出，同样 36 次输入连续输出 32 帧、零重置；结束时排空剩余帧后共输出 36 帧。此测试只检查解码，不打开窗口或作视觉验收。
- 最小修复：原生 WK 页面默认附加 `decoder=hardware`，复用已有配置；显式参数优先，普通网页默认不变。Swift 类型检查、相关 41 项测试、个人 Mac 构建、签名及打包检查通过。
- 已后台替换 Mac 包，旧包保存为压缩备份。当前进程未被重启；**用户需自行退出并重新打开 Mac 应用后复测真实投屏画面**。其他分辨率、低帧率和实际无线延迟未据此宣称通过。

证据：`captures/mirroring-diagnosis/` 中的诊断快照、纯解码对照日志、构建与打包检查日志，以及安装和同 bundle ID 副本检查记录。

### 后续修正：启动时简化模型闪现（2026-09-29）

用户观察到启动时先显示简化模型，再切为精细模型。源码确认了两个原因：资源检查的未知状态被当作不可用；精细模型加载期间的 Suspense 占位也使用了简化机身。

现将未知、可用、不可用三态分开：检查与加载期间显示 `Loading phone…`；精细机身、底部、屏幕与 Dynamic Island 在同一加载边界内一起出现；资源不可用时才使用简化模型。原 GLB、材质和物理逻辑保留。

相关 lint、类型检查、现有资源可用性测试通过。后台构建个人 Mac 包，原始模型与包内模型一致性、签名和运行包检查通过后替换；当时留下的旧包压缩备份已按后续要求删除。视觉效果由用户在下次打开应用时确认，主代理不启动或切换窗口进行检查。

## 视觉验收交接

用户保持应用在前台，按以下清单检查：

1. **默认屏幕**：依次切换 Marble、Tracking、Screen mirroring；未连接手机时不应出现整片绿色默认屏幕，预览区应显示手机模型。
2. **模型外观**：拖动旋转并缩放，查看正面、侧面和背面；检查机身比例、圆角、摄像头、材质，有无错位、穿模或异常拉伸，以及三个工作区是否一致。
3. **深浅外观**：在应用设置中切换 Light / Dark；文字和按钮清楚，模型没有黑成一团或亮到细节全白，布局没有重叠或裁切。检查后可恢复 System。
4. **画面恢复**：切换工作区，再切到其他应用后返回；模型应重新显示，画面不应持续空白。
5. **屏幕内容**：Screen mirroring 选择本地视频或实际连接手机；检查画面方向、比例和裁切是否正常。

此前截图中原生预览区为空。临时诊断记录显示页面处于 `visibility=hidden`、动画帧数为零，画布尺寸正常、WebGL context 有效且未丢失，也没有捕获到页面错误。同一构建在浏览器能显示模型。同期观察到其他桌面操作切换窗口，因此不能把这些遮挡状态下的截图作为最终视觉验收证据。

诊断记录保留于 `captures/experience-polish/native-visibility-diagnostic.log`。`marble-dark.png` 和 `tracking-dark.png` 为当时的诊断截图，**不代表最终验收通过**。正式包已移除临时诊断，并保留原有后台暂停机制。

## 用户真机验收

1. Mac 打开 Phone 3D Studio，点击 Connect iPhone。
2. iPhone 扫码后打开 Tracking，点击 Start tracking，等待连接与追踪就绪。
3. 手机屏幕朝上、顶部朝向 Mac，后置相机保持在有纹理的表面上方；在 Mac Marble 点击 Start round。
4. 连续体验五分钟，完成十次接球、三次补球，并测试一次中断后重新校准开局。
5. 确认连接提示、跟手程度、跨屏画面与震动反馈。合成输入、编译成功和安装成功均不代替这项验收。
